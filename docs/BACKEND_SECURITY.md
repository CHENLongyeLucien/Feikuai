# Backend boundaries and operation

The API is a single Fastify process with SQLite WAL, foreign keys, `synchronous=FULL`, and a 5-second busy timeout. Invariant-bearing migrations run idempotently; Drizzle read models are in `apps/api/src/db/schema.ts`. There is one serialized relayer worker, up to two concurrent analyses, durable job leases, and independent periodic chain observation. Multiple API replicas against this local SQLite deployment are unsupported.

Opaque session tokens are random 32-byte values; only their SHA-256 hashes are stored. SIWE challenges bind the configured origin/URI/chain, wallet, random nonce, browser pre-auth cookie, exact message and five-minute expiration. Challenge consumption and session creation share a transaction. An ordinary login signature has no payment authority. Every protected object query uses the session tenant. Mutations require approved Origin, session CSRF, roles and an idempotency key. The cookie is HttpOnly/SameSite Strict; HTTP is permitted only for loopback development. `SESSION_SECRET` is reserved configuration; opaque sessions do not use a signed-cookie secret.

Invoice originals are private durable blobs, written, fsynced and renamed before database references. PDF.js runs in a worker with a 128 MiB old-generation limit and a 15-second timeout. Limits are 10 MiB, 20 pages, and 40,000 extracted UTF-16 characters. Entire oversized input is rejected; it is never silently truncated. Source offsets refer to stored page text, and quoted spans are checked again after schema validation. Unsupported/encrypted/scanned/corrupt inputs return explicit errors. Original files never become public static assets.

Two versioned prompts use the OpenAI Responses API with strict `text.format`, strict empty-argument read tools, `store:false`, a 3,500-token output budget, up to four model requests, three Finance tool calls, one repair and one transient retry, within a 60-second maximum stage deadline. Installed SDK types and the official [structured-output](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses) and [function-tool](https://developers.openai.com/api/docs/guides/function-calling) documentation informed the adapter. `store:false` is not a universal zero-retention promise. Provider/model availability and account retention remain account-specific. Live calls require an explicit key and model and never fall back to fixtures. Fixture runs have zero provider requests and explicit provenance.

Agents cannot choose tenants, SQL, paths, payable IDs, wallets, URLs, registry mutations, signatures or payment tools. Application checks independently reload supplier/payable facts, validate exact integer amounts, source pointers, identity, versions, token and recipient. Suspicious prose requires reviewer acknowledgment; acknowledgment cannot override a hard mismatch. Manual application holds persist through analysis reruns.

Every exportable proposal is potentially signed outside the API. Outstanding-packet checks apply across all cases for the same registry invoice key. Concurrent proposal commits recheck case/document/record versions and invoice-wide outstanding proposals. A revision preserves the invoice key and cannot silently revoke prior authority.

The relayer key must match the distinct manifest relayer role. The backend contains no approver key configuration. It simulates exact signed calldata, reserves one EOA nonce, prepares and signs, computes the hash, then persists raw bytes/envelope/hash before broadcast. Reserved or prepared transactions block competing relayer nonces until resolved. Restart observes the known hash and chain before any permitted identical rebroadcast. Cancellation pending, a hold, revision, expiry or consumed nonce prevents new submission/rebroadcast but never stops receipt observation.

Settlement requires the pinned chain, exact vault, successful executed receipt, matching block/transaction identity, exact decoded calldata and eligible signature, every emitted payment field, fixed policy, consumed nonce/invoice digest and matching DEMO Transfer. Signed timestamps are checked in calldata; they are intentionally absent from the contract event. All settlement/projection/consumption/event writes are atomic and unique by vault/invoice and transaction/log. External executions are scanned from the deployment block and matched to frozen proposals, even without an imported authorization. Unmatched onchain consumption is held as inconsistent, never presented as a normal unpaid case.

Evidence ZIP downloads are authenticated private exports. They may contain still-usable signatures and must remain private. The API does not expose public signature downloads. Original manifests are immutable; receipts and attempts are separate export artifacts. Database administrators can still alter the database; this is not an independently tamper-proof log.

Tests may configure `SF_CRASH_AT=after-persist|after-broadcast` and `SF_JOB_LEASE_MS` only with `NODE_ENV=test`. These controls terminate the real process at the outbox boundaries; they are inactive in deployed environments. Unit tests inject a provider only in test mode; their results are simulated adapter checks, not live model measurements.

Remaining external checks: actual OpenAI calls need credentials and an available model; Fuji execution needs separately controlled approver/relayer/deployer wallets and test AVAX, deployed/funded DEMO vault, reviewed registry and freshly pinned approver build. Local unit tests do not prove these external runs occurred.
